# 우리 동네 생활권 진단 Agent 설계 (v2)

작성일: 2026-11-15. 마감: 2026-11-20(금) 10:00. 1인 참가.

## 1. 목적

도민이 "우리 동네 주민 중 몇 %가 걸어서 15분 안에 약국에 갈 수 있나"를 물으면, Agent가 제주데이터허브 데이터로 읍면동별 보행 접근성을 계산해 지도와 설명으로 답한다. 제주빅데이터센터 PC에서 비전문가가 직접 실행한다.

## 2. 주제 선정 근거

리더보드 제출 62건 중 54건의 제목을 확인했다(11/15 기준). 범용 데이터 질의형이 약 15건, 상권·창업이 약 11건, 관광이 약 10건이다. 생활 인프라 접근성을 다룬 제출은 없었다. 상호평가는 두 제출물을 비교해 고르는 방식이라 겹치지 않는 주제가 유리하다고 판단했다.

## 3. 사용자와 장면

개인 길찾기는 다루지 않는다. 그건 지도 서비스가 더 잘한다. 이 Agent는 동네 단위로 비교하고 근거를 만든다.

- 주민자치위원: "우리 동에 공공심야약국이 필요하다"고 건의할 근거를 찾는다.
- 읍면동 복지 담당자: "70대 이상 인구 기준으로 의원 접근이 가장 나쁜 동네 5곳은?"
- 버스 노선 의견을 내는 주민: "정류소까지 10분 넘게 걸리는 주민 비율이 높은 마을은?"

## 4. 목표, 비목표, 반목표

목표
- 시설 종류와 기준 시간(5/10/15분)을 골라 읍면동별 도달 가능 여부와 비율을 계산한다.
- 70대 이상 등 연령별 인구로 가중해 "취약한 동네" 순위를 낸다.
- 결과마다 지도, 표, 세 줄 요약, 출처, 한계를 보여준다.

비목표
- 실시간 길찾기를 하지 않는다.
- 진료 시간, 휴일 운영은 다루지 않는다. 데이터에 없다.

반목표
- LLM이 지어낸 숫자가 화면에 나온다.
- 폐업한 시설이 결과에 섞인다.
- 센터 PC에서 설치하다 막힌다.

## 6. 접근 방식

| 안 | 내용 | 판단 |
|---|---|---|
| A. 직선거리 | 출발점에서 시설까지 직선거리를 보행속도로 환산 | 빠르지만 하천, 오름, 도로 단절을 무시한다 |
| B. 보행망 거리 | OSM 보행망 위 최단거리로 계산 | 선택. 미리 계산해두면 센터 PC에서도 빠르다 |
| C. 외부 길찾기 API | 호출마다 경로 API 사용 | 키와 호출 한도에 묶이고 오프라인에서 안 된다 |

출발점은 읍면동 안에 일정 간격으로 찍은 격자점(예: 250m)을 쓴다. 각 점에서 시설까지 보행 시간을 미리 계산해 파일로 저장한다. 실행 중에는 이 표를 조회만 한다.

## 6-1. 보행자 유형(페르소나)

보행망 위 거리(m)를 미리 계산해 두고, 유형별 속도로 나눠 시간을 낸다. 유형을 바꿔도 재계산이 필요 없다.

| 유형 | 속도 | 근거 | 인구 가중 | 기본 시설 |
|---|---|---|---|---|
| 일반 성인 | 1.00 m/s | 일반지역 신호 기준, 일반인 하위 15% 1.00~1.01 | 20~60대 | 약국, 의원, 정류소 |
| 어르신 | 0.85 m/s | 고령자 하위 15% | 70대 이상 | 의원, 보건진료소, 약국, 치매안심센터, 정류소 |
| 보조기구 사용 어르신 | 0.73 m/s | 지팡이·휠체어 고령자 하위 15% | 70대 이상 | 위와 같음 |
| 아이 동반 보호자 | 0.80 m/s | 어린이보호구역 신호 기준 (가정) | 10세 미만 | 소아청소년과 의원, 약국, 도서관 |

근거: 한음 외(2020), 한국ITS학회논문지. 아이 동반 속도는 직접 측정 연구를 찾지 못해 보호구역 기준을 가정으로 쓰고 한계에 적는다. 경사는 반영하지 않는다.

사용자는 유형을 고르고, 기준 시간(5/10/15/20분)과 시설을 바꿀 수 있다.

## 7. Agent 구성

LLM이 하는 일
- 질문에서 시설 종류, 진료과목, 지역, 기준 시간, 대상 연령을 뽑는다.
- 결과 표를 세 줄 요약으로 쓴다.
- 데이터로 답할 수 없는 질문이면 답하지 않고 이유를 말한다.

도구
| 도구 | 하는 일 |
|---|---|
| parse_query | 질문을 조건으로 바꾼다 (LLM) |
| reach_by_emd | 읍면동별 도달 가능 격자 비율과 인구 가중 비율 |
| nearest | 특정 지점/동네에서 가장 가까운 시설 N곳과 보행 시간 |
| rank_gaps | 취약 동네 순위 |
| make_map | 지도 생성 (folium) |
| explain | 요약과 한계 문장 (LLM) |

숫자는 항상 도구 결과에서만 온다.

## 8. 화면

```
[질문 입력                                   ] [묻기]
예시 버튼: 걸어서 약국 / 소아과 15분 / 어르신 취약 동네

[지도: 읍면동 색칠 + 시설 점]   [요약 세 줄]
                               [표: 동네별 비율]
                               [출처 · 기준일 · 한계]
조건 직접 고르기: 시설 ▾  시간 ▾  지역 ▾  연령 ▾   (LLM 없이 실행)
```

## 9. 실행 환경

- Python 3.11, Streamlit, folium, pandas. Windows용 run.bat 하나로 설치와 실행.
- LLM: Qwen3.5-4B를 로컬 실행 (GTX 1060 3GB에 맞춤). 예비로 Gemini Flash 무료 API.
- LLM이 없거나 실패하면 조건 직접 고르기 모드로 그대로 쓸 수 있다.
- 데이터허브 API 키는 제출물에 넣지 않는다. 미리 수집한 데이터를 포함하고, 갱신 스크립트와 키 발급 방법을 매뉴얼에 쓴다.

## 10. 검증

- 질문 30개 평가 세트: 조건 추출 정확도, 실행 성공률.
- 표본 20곳 보행 시간을 지도 서비스 도보 시간과 비교해 오차를 보고한다.
- 주소 좌표 변환 성공률, 폐업 제외 건수를 보고한다.
